# ملفات — لوحة إدارة أعمال الجهات الحكومية

موقع داخلي لمتابعة وتنظيم الأعمال: **شركات ← مشاريع ← مراحل ← 9 نقاط** لكل مرحلة،
مع رفع عدة ملفات (Word + PDF + صور) داخل كل نقطة.

- الاستضافة: **GitHub Pages** (مجاني)
- قاعدة البيانات + الحسابات + تخزين الملفات: **Supabase** (الخطة المجانية)
- الدخول بحساب واسم مستخدم وكلمة مرور فقط — لا يوجد تسجيل ذاتي، أنت من ينشئ الحسابات
- التكلفة الإجمالية: **صفر**

## خطوات التشغيل (مرة واحدة، حوالي 15 دقيقة)

### 1) إنشاء مشروع Supabase مجاني

1. ادخل على <https://supabase.com> ← **Start your project** ← سجّل بحساب GitHub.
2. **New project** ← اختر اسماً (مثلاً `molafat`) وكلمة مرور لقاعدة البيانات (احفظها).
3. اختر أقرب منطقة (مثلاً `eu-central` أو `me-south`) ← **Create new project** وانتظر دقيقتين.

### 2) إنشاء الجداول والحماية

1. من القائمة الجانبية: **SQL Editor** ← **New query**.
2. انسخ محتوى الملف [`supabase/schema.sql`](supabase/schema.sql) بالكامل والصقه.
3. اضغط **Run**. يجب أن تظهر رسالة `Success`.

هذا الملف ينشئ الجداول، ويفعّل **Row Level Security** (لا يستطيع أي شخص غير مسجّل
قراءة أو كتابة أي بيان)، وينشئ مجلد تخزين **خاص** للمرفقات.

### 3) إيقاف التسجيل الذاتي (مهم للأمان)

**Authentication ← Sign In / Providers ← Email**:

- أطفئ **Allow new users to sign up** (أو `Enable sign ups`).
- أطفئ **Confirm email** — الحسابات تُنشأ يدوياً ولا تحتاج تأكيد بريد.

بهذا لا يستطيع أحد إنشاء حساب لنفسه إطلاقاً.

### 4) إنشاء حسابات المستخدمين

**Authentication ← Users ← Add user ← Create new user**:

- Email: `tarek@work.com` (استخدم أي اسم مستخدم + `@work.com`)
- Password: كلمة مرور قوية
- فعّل **Auto Confirm User**

المستخدم يدخل الموقع باسم `tarek` فقط، والموقع يكمل الباقي تلقائياً.
كرّر الخطوة لكل شخص تريد مشاركته العمل — الجميع يرى نفس البيانات ويعمل عليها معاً.

### 5) ربط الموقع بقاعدة البيانات

من **Project Settings ← API** انسخ:

- `Project URL`
- `anon` `public` key

ثم عدّل ملف [`public/config.js`](public/config.js):

```js
window.__APP_CONFIG__ = {
  SUPABASE_URL: 'https://xxxxxxxx.supabase.co',
  SUPABASE_ANON_KEY: 'eyJhbGciOi...',
  LOGIN_DOMAIN: 'work.com',
}
```

> مفتاح `anon` مفتاح عام بطبيعته ولا خطر منه: كل صلاحياته محكومة بسياسات
> Row Level Security التي تمنع أي شيء بدون تسجيل دخول.

### 6) الرفع على GitHub Pages

```bash
cd Website
git add -A
git commit -m "أول إصدار"
gh repo create molafat --private --source=. --push   # أو أنشئ المستودع يدوياً على github.com
```

ثم من صفحة المستودع: **Settings ← Pages ← Build and deployment ← Source: GitHub Actions**.

كل `git push` على فرع `main` يبني الموقع وينشره تلقائياً.
الرابط يظهر في **Settings ← Pages** ويكون بالشكل:
`https://<اسم-المستخدم>.github.io/molafat/`

> ملاحظة: مستودع خاص (private) يحتاج GitHub Pro لتفعيل Pages.
> إن كان المستودع عاماً فلا مشكلة أمنية: الكود فقط هو المنشور، أما البيانات
> والملفات فمحفوظة في Supabase ولا تُفتح إلا بتسجيل دخول.

## الأمان — ما الذي يحمي البيانات

| الطبقة | الحماية |
|--------|---------|
| قاعدة البيانات | RLS مفعّل على كل الجداول: `to authenticated` فقط. الزائر غير المسجّل لا يقرأ ولا يكتب أي شيء |
| الملفات | مجلد تخزين خاص (`public = false`) — تُفتح الملفات عبر روابط موقّعة تنتهي بعد ساعة |
| الحسابات | لا تسجيل ذاتي؛ الحسابات تُنشأ من لوحة Supabase فقط |
| الجلسة | JWT يُجدَّد تلقائياً، ويُلغى فوراً عند تسجيل الخروج |

للحماية القصوى: فعّل **MFA** على حساب Supabase وحساب GitHub.

## حدود الخطة المجانية (كافية جداً لهذا الاستخدام)

- قاعدة بيانات: 500 ميجابايت
- تخزين ملفات: 1 جيجابايت
- عدد المستخدمين: حتى 50,000 شهرياً
- GitHub Pages: 1 جيجابايت للموقع، بلا حد للزيارات العملية

⚠️ مشروع Supabase المجاني **يُوقَف مؤقتاً بعد 7 أيام بلا أي استخدام**، ويُستأنف
بضغطة زر من لوحة التحكم. الاستخدام الأسبوعي العادي يمنع ذلك تماماً.
